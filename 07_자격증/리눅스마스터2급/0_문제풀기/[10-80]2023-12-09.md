# 1
> [문제] 다음 (괄호) 안에 들어갈 내용으로 알맞은 것은?
> 10GB 용량의 하드디스크 8개가 장착된 시스템이다.
> 하나의 스페어(Spare) 디스크를 구성하고, 나머지 디스크로 RAID-5로 구성하려고 한다.
> 이 경우에 실제로 사용 가능한 용량은 ( 괄호 ) GB가 된다.

[보기]
- 40
- 50
- 60
- 70

[정답]
(3) 60

[해설]
> 8개 중 1개를 스페어로 뺴면 RAID-5에 참여하는 디스크는 7개이다.
> RAID-5는 디스크 1개 용량만큼을 패리티로 분산 저장하므로 실제 사용 가능 용량은 (참여 디스크 수 -1) * 디스크 용량 = (7 - 1) x 10GB = 60GB이다.
> RAID-5 의 사용 가능 용량은 (N − 1) × 디스크 용량(N = 데이터 디스크 수)이며, 스페어 디스크는 평소 대기하다가 장애 시 자동 대체되므로 용량 계산에서 제외한다.


[정리]
- `RAID-0 (스트라이핑)` : 데이터를 여러 디스크에 쪼개서 분산 저장하는 방식 (속도는 가장 빠르나, 1개만 고장 나도 전체 데이터 파괴)
- `RAID-1 (미러링)` : 똑같은 데이터를 다른 디스크에 그대로 복사하는 방식 (안정성은 가장 높으나, 실사용 용량이 절반으로 반토막 듦)
- `RAID-2 (해밍 코드)` : 에러 정정을 위해 '해밍 코드'를 사용하는 방식 (계산이 복잡하고 비효율적이라 지금은 안 씀)
- `RAID-3 (동기식 비트/바이트 패리티)` : 데이터를 바이트 단위로 쪼개고, 복구용 패리티를 전용 디스크 1개에 몰아서 저장하는 방식
- `RAID-4 (독립식 블록 패리티)` : 데이터를 블록 단위로 쪼개고, 복구용 패리티를 전용 디스크 1개에 몰아서 저장하는 방식
- `RAID-5 (분산 패리티)` : 복구용 패리티를 모든 디스크에 골고루 분산 저장하여, RAID-4의 단점(패리티 디스크 병목 현상)을 해결한 방식
- `RAID-6 (복수 분산 패리티)` : RAID-5에서 패리티를 2개로 늘려 분산 저장하는 방식 (디스크가 동시에 **2개까지 고장 나도** 데이터 복구 가능)
- `RAID-10 (RAID 0+1)` : 디스크들을 먼저 똑같이 복사(RAID 1)한 후, 그 묶음들을 다시 쪼개서 저장(RAID 0)하는 방식 (속도와 안정성을 모두 잡은 고성능 방식)
- `패리티` : 데이터 훼손 시 원상복구를 위해 사용하는 '오류 복구용 힌트 데이터'

# 2
[문제]
> 다음 설명에 해당하는 RAID 관련 기술로 알맞은 것은?
> 연속된 데이터를 여러 개의 디스크에 라운드 로빈(Round Robin) 방식으로 기록하는 기술로
> 하나의 디스크에서 읽어 들이는 것보다 더 빠르게 데이터를 읽거나 쓸 수 있다.

[보기]
- 스트라이핑
- 미러링
- 패리티
- ECC(Error Check & Correction)

[정답]
- 스트라이핑(Striping)

[해설]
> 데이터를 일정 크기로 나눠 여러 디스크에 분산 기록하여 입출력을 병렬화함으로써 속도를 높이는 기술은 스트라이핑(Striping)이다.
> RAID-0 의 핵심 기술이다.
> 스트라이핑은 속도 향상, 미러링은 데이터 보호, 패리티는 적은 용량 손실로 장애 복구를 제공한다.
> RAID-0 은 스트라이핑만, RAID-1 은 미러링, RAID-5 는 스트라이핑+분산 패리티를 결합한다.

[정리]
- `스트라이핑(Striping)` : 데이터를 여러 디스크에 칼로 자르듯 쪼개서 나누어 저장하는 기술 (읽기/쓰기 속도가 획기적으로 빨라짐)
- `미러링(Mirroring)` : 데이터를 거울을 보듯 다른 디스크에 똑같이 복사하여 이중화하는 기술 (디스크 고장 시 완벽한 백업 제공)
- `패리티(Parity)` : 데이터 훼손 시 원상복구를 위해 사용하는 '오류 복구용 힌트 데이터' (RAID-3, 4, 5, 6 등에서 사용)
- `ECC(Error Check & Correction)` : 데이터 전송 중 발생한 에러를 스스로 찾아내고 올바르게 수정(정정)하는 기술 (RAID-2의 해밍 코드가 대표적)

# 3
[문제]
> 다음 중 LVM 구성할 때 가장 먼저 생성되는 것은?

[보기]
- VG(Volume Group)
- LV(Logical Volume)
- PV(Physical Volume)
- PE(Physical Extend)

[정답]
- PV(Physical Volume)

[해설]
> LVM 구성은 물리적인 디스크/파티션을 PV(Physical Volume)로 초기화하는 것부터 시작한다.
> PV 가 있어야 그것을 묶어 VG 를 만들 수 있다.
> VG(Volume Group)는 여러 PV 를 묶은 단위로, PV 생성 이후에 만든다.
> LV(Logical Volume)는 VG 의 공간을 잘라 만든 논리 볼륨으로 가장 마지막 단계이다.
> PV(Physical Volume)는 LVM 의 최하위 구성 요소로 가장 먼저 생성한다.
> PE(Physical Extent)는 PV 를 구성하는 최소 할당 단위로, 사용자가 별도로 '생성'하는 대상이 아니다.
> LVM 구성 순서는 PV(pvcreate) → VG(vgcreate) → LV(lvcreate) 이며, VG 의 할당 단위가 PE, LV 의 할당 단위가 LE(Logical Extent)이다.

[정리]
- `LVM (논리 볼륨 관리자)` : 여러 개의 물리적인 하드디스크를 하나의 가상 디스크처럼 묶고, 용량을 마음대로 조절할 수 있게 관리해 주는 기술
- `PV (Physical Volume / 물리 볼륨)` : LVM에서 사용하기 위해 통째로 준비한 실제 물리적인 하드디스크나 파티션
- `VG (Volume Group / 볼륨 그룹)` : 준비된 PV(물리 볼륨)들을 하나로 커다랗게 묶어 만든 '가상 디스크 풀(Pool)'
- `LV (Logical Volume / 논리 볼륨)` : 거대한 VG(볼륨 그룹)에서 사용자가 필요한 만큼 용량을 쪼개어 만든 '최종 가상 파티션' (실제 마운트해서 쓰는 공간)
- `PE (Physical Extent / 물리 익스텐트)` : PV가 VG로 묶일 때 쪼개지는 LVM의 '기본 저장 단위 블록' (보통 기본값은 4MB)
- `Pool` : 여러 개를 하나로 모아둔 '거대한 공동 자원 저장소(웅덩이)'

# 4
[문제]
> 다음 중 프린터 큐의 작업 정보를 확인하는 명령어로 알맞은 것은?

[보기]
- lp
- lpr
- lprm
- lpstat

[정답]
- lpstat

[해설]
> CUPS 환경에서 프린터 상태와 큐에 쌓인 작업 정보를 확인하는 명령은 lpstat 이다.
> lp 는 CUPS 계열에서 인쇄 작업을 큐에 등록(출력 요청)하는 명령이다.
> lpr 은 BSD 계열의 인쇄 요청 명령으로, 작업 정보 확인이 아니라 출력 요청용이다.
> lprm 은 인쇄 큐에 등록된 작업을 삭제(취소)하는 명령이다.
> lpstat 은 프린터·큐·작업 상태를 조회하는 명령으로 옳다.
> CUPS 계열 명령: lp(요청)/lpstat(상태)/cancel(취소),
> BSD 계열 명령: lpr(요청)/lpq(큐 확인)/lprm(삭제)로 짝지어 외우면 좋다.

[정리]
- `CUPS (Common Unix Printing System)` : 리눅스 및 유닉스 계열 운영체제에서 프린터를 관리하고 인쇄 요청을 처리해 주는 표준 오픈소스 인쇄 시스템
- `BSD 계열 인쇄 시스템` : 유닉스 전통 방식의 인쇄 시스템으로, lpr, lprm, lpq, lpc 등의 명령어를 사용하여 프린트를 제어하는 방식
- `lp` : System V 계열에서 주로 사용하는 인쇄 명령어로, 지정한 파일의 출력을 프린터 큐에 요청하는 명령어
- `lpr (Line Printer)` : BSD 계열에서 사용하는 인쇄 명령어로, 파일을 프린터 버퍼(출력 대기열)에 전송하여 인쇄를 요청하는 명령어
- `lprm (Line Printer Remove)` : 프린터 대기열(큐)에서 출력 대기 중인 인쇄 작업(Job)을 취소하고 삭제하는 명령어
- `lpstat (Line Printer Status)` : 현재 프린터의 연결 상태와 대기열에 쌓인 인쇄 작업들의 목록 및 진행 상황을 확인하는 명령어

# 5
[문제]
> 다음 설명에 해당하는 명칭으로 알맞은 것은?
> 리눅스 및 유닉스 계열 운영체제에서 사운드를 만들고 캡처하는 인터페이스로
> 표준 유닉스 시스템 콜(POSIX)에 기반을 두고 있다.
> 프로젝트 초기에는 Free Software이었으나 사유화되기도 했다.

[보기]
- ALSA
- CUPS
- SANE
- OSS

[정답]
- OSS

[해설]
> 유닉스 표준 시스템 콜(open/read/write/ioctl)을 기반으로 사운드를 입출력하는 인터페이스이며 초기에는 자유 소프트웨어였다가 일부 상용화된 것은 OSS(Open Sound System)이다.
> ALSA(Advanced Linux Sound Architecture)는 OSS 를 대체하기 위해 만들어진 리눅스 표준 사운드 시스템으로, 현재 커널의 기본 사운드 드라이버이다.
> CUPS 는 사운드가 아니라 인쇄(프린팅) 시스템이다.
> SANE 는 스캐너 제어용 인터페이스이다.
> POSIX 시스템 콜 기반에 초기 자유 소프트웨어였다가 사유화된 사운드 인터페이스는 OSS 이다.
> 리눅스 사운드 역사: 초기 OSS → 한계 보완을 위한 ALSA 로 전환되었고, 현재 표준은 ALSA(상위에 PulseAudio/PipeWire 등 사운드 서버)이다.

[정리]
- `POSIX (Portable Operating System Interface)` : 서로 다른 유닉스/리눅스 운영체제 간의 프로그램 호환성을 위해 만든 API 및 시스템 인터페이스 표준 규격
- `시스템 콜 (System Call)` : 일반 응용 프로그램이 커널(OS의 핵심)에 접근하여 파일 읽기/쓰기, 메모리 할당 같은 보호된 기능을 요청하는 통로
- `CUPS (Common Unix Printing System)` : 리눅스 및 유닉스 계열 운영체제에서 프린터를 관리하고 인쇄 요청을 처리해 주는 표준 오픈소스 인쇄 시스템
- `SANE (Scanner Access Now Easy)` : 리눅스 및 유닉스 계열 운영체제에서 평판 스캐너, 핸드 스캐너 등 이미지 입력 장치를 표준화된 방식으로 제어하는 API 시스템
- `PulseAudio` : 여러 프로그램의 소리를 하나로 믹싱하고 네트워크로 전송할 수 있게 해주는 데스크톱 리눅스의 전통적인 사운드 서버 (서버 가상화/오디오 제어)
- `PipeWire` : PulseAudio의 뒤를 잇는 차세대 멀티미디어 서버로, 낮은 지연 시간(Low Latency)으로 오디오와 비디오 스트림을 통합하여 처리하는 기술

# 6
[문제]
다음 중 스캐너 사용과 관련된 프로그램으로 알맞은 것은?

[보기]
- ALSA
- CUPS
- SANE
- LPRng

[정답]
- SANE

[해설]
> 리눅스/유닉스에서 스캐너 장치를 제어하는 표준 API 이자 프로그램은 SANE(Scanner Access Now Easy)이다.
> ALSA 는 사운드(오디오) 시스템이다.
> CUPS 는 인쇄(프린팅) 시스템이다.
> SANE 는 스캐너 접근용 인터페이스로 옳다.
> LPRng 는 BSD 프린팅 시스템을 개선한 인쇄 스풀링 소프트웨어이다.
> 장치별 리눅스 인터페이스: 사운드=ALSA/OSS, 인쇄=CUPS/LPRng, 스캐너=SANE 로 묶어 기억한다. SANE 는 명령행 도구 scanimage 와 GUI 프런트엔드 XSane 등을 제공한다.

[정리]
- `LPRng (LPR Next Generation)` : 전통적인 BSD 계열 인쇄 시스템(lpr)의 보안성과 기능을 획기적으로 향상시킨 차세대 프린터 스풀러 시스템
- `스풀링(Spooling)` : CPU와 느린 주변장치(프린터 등) 간의 속도 차이를 극복하기 위해, 하드디스크의 일부 공간을 버퍼로 사용하여 데이터를 임시로 저장해 두는 기술
- `BSD 계열 인쇄 시스템` : 유닉스 전통 방식의 인쇄 시스템으로, lpr, lprm, lpq, lpc 등의 명령어를 사용하여 프린터 대기열과 출력을 제어하는 방식
- `Spool` : 실타래(얼레), 데이터를 임시로 감아서 대기시켜 두는 통

# 7
[문제]
> 다음 중 데비안 계열 리눅스에서 환경 설정 파일도 포함해서 vsftpd 패키지를 제거하는 명령으로 알맞은 것은?

[보기]
- apt-get purge vsftpd
- apt-get remove vsftpd
- apt-get erase vsftpd
- apt-get delete vsftpd

[정답]
- apt-get purge vsftpd

[해설]
> apt-get purge 는 패키지뿐 아니라 관련 환경 설정 파일까지 함께 제거한다. 따라서 'apt-get purge vsftpd' 가 옳다.
> apt-get remove 는 패키지 본체만 제거하고 설정 파일은 남겨 둔다.
> erase 는 apt-get 의 서브명령이 아니다(rpm 의 -e/erase 와 혼동).
> delete 도 apt-get 의 서브명령이 아니다.

[정리]
- `데비안 (Debian) 계열` : 자유 소프트웨어 정신을 기반으로 하며, 우분투(Ubuntu)와 리눅스 민트(Linux Mint)가 속한 가장 대중적인 가문 (패키지: .deb / 관리자: apt)
- `레드햇 (Red Hat) 계열` : 기업용/서버용 시장을 꽉 잡고 있으며, RHEL, 록키 리눅스(Rocky Linux), 페도라(Fedora)가 속한 가문 (패키지: .rpm / 관리자: dnf, yum)
- `슬랙웨어 (Slackware) 계열` : 유닉스의 전통적인 구조를 가장 있는 그대로 유지하여 단순하고 수동 설정이 많은 매니아 및 학습용 가문 (openSUSE가 여기서 파생됨)
- `apt` : 데비안/우분투 계열에서 패키지 설치, 업데이트, 삭제 등을 사람이 읽기 편한 진행 상황과 인터페이스로 통합하여 관리해 주는 최신 명령어
- `apt-get` : 전통적으로 스크립트나 시스템 자동화에서 주로 사용하는 데비안/우분투 계열의 구형 패키지 관리 명령어
- `apt-get purge vsftpd` : vsftpd 패키지를 삭제할 때, 프로그램 본체뿐만 아니라 기존에 설정해 둔 모든 환경 설정 파일(Config)까지 싹 다 강제로 지우는 명령어
- `apt-get remove vsftpd` : vsftpd 패키지의 프로그램 본체만 삭제하고, 나중에 재설치할 때를 대비하여 기존 환경 설정 파일은 시스템에 그대로 남겨두는 명령어
- `vsftpd (Very Secure FTP Daemon)` : 리눅스 및 유닉스 환경에서 보안성과 성능, 그리고 안정성을 최우선으로 고려하여 만든 가장 대중적인 오픈소스 FTP 서버 소프트웨어

# 8
[문제]
> 다음 중 rpm 명령으로 의존성이 있는 패키지를 제거하는 명령으로 알맞은 것은?

[보기]
- rpm -d nmap --nodeps
- rpm -e nmap --nodeps
- rpm erase nmap -- nodeps
- rpm delete nmap -nodeps

[정답]
- rpm -e nmap --nodeps

[해설]
> rpm 의 패키지 삭제 옵션은 -e(erase)이고, 의존성 검사를 무시하고 강제로 제거할 때는 --nodeps 를 붙인다. 따라서 'rpm -e nmap --nodeps' 가 옳다.
> rpm 에는 -d 삭제 옵션이 없다(삭제는 -e).
> -e 와 --nodeps 조합으로 의존성을 무시하고 제거하므로 옳다.
> erase 라는 단어형 서브명령은 rpm 에 없다.
> delete 서브명령도 없고 -nodeps 는 옵션 표기(--nodeps)도 틀렸다.

[정리]
- `rpm` : 레드햇 계열 리눅스에서 소프트웨어를 설치, 삭제, 조회, 검증하기 위해 사용하는 전통적인 저수준 패키지 관리 도구
- `rpm -ivh` : 새로운 패키지를 설치(`-i`)할 때, 진행 과정을 주해(`-v`)와 해시 기호(`#`, `-h`)로 상세히 화면에 출력하는 설치 기본 명령어
- `rpm -e` : 시스템에 설치된 특정 패키지를 깨끗이 제거(Erase)하는 명령어
- `rpm -qa` : 현재 시스템에 설치된 모든(All) 패키지의 목록을 한눈에 조회(Query)하는 명령어
- `rpm -qi` : 설치된 특정 패키지에 대한 상세 정보(Information)를 보여주는 명령어
- `rpm -ql` : 특정 패키지를 설치했을 때 시스템의 어느 경로(List)에 파일들이 생성되었는지 확인하는 명령어
- `--nodeps` : 패키지를 설치하거나 삭제할 때, 얽혀 있는 의존성(Dependencies) 검사를 강제로 무시하고 진행하도록 만드는 옵션

# 9
[문제]
> 다음은 확장 패키지 관련 저장소를 설치하는 과정이다. (괄호) 안에 들어갈 내용으로 알맞은 것은?
```shell
# yum install ( 괄호 )
```

[보기]
- epel
- epel-repository
- epel-release
- epel-download

[정답]
- epel-release

[해설]
> EPEL(Extra Packages for Enterprise Linux) 저장소를 추가하려면 epel-release 패키지를 설치한다. 따라서 'yum install epel-release' 가 옳다.
> epel 만으로는 yum 이 설치할 패키지를 특정하지 못한다.
> epel-repository 라는 패키지명은 존재하지 않는다.
> epel-release 는 EPEL 저장소 설정(.repo)과 GPG 키를 제공하는 정식 패키지명이다.
> epel-download 라는 패키지명도 존재하지 않는다.
> EPEL 은 RHEL/CentOS 계열에서 기본 저장소에 없는 추가 패키지를 제공하는 커뮤니티 저장소로, epel-release 설치 후 /etc/yum.repos.d/ 에 저장소 정의가 추가된다.

[정리]
- `yum` : 레드햇 계열 리눅스에서 인터넷 저장소를 통해 의존성(Dependency)이 있는 패키지들을 자동으로 다운로드하고 설치해 주는 고수준 패키지 관리 도구
- `EPEL (Extra Packages for Enterprise Linux)` : 레드햇/CentOS 계열의 기본 저장소에 없는 유용한 고성능 추가 패키지들을 제공하는 공식 커뮤니티 확장 저장소
- `epel-release` : 시스템에 EPEL 저장소 활성화 설정 파일과 인증 키를 자동으로 심어주는 패키지 명칭
- `/etc/yum.repos.d/` : yum이 패키지를 다운로드할 때 참조하는 인터넷 저장소(Repository)들의 주소 설정 파일(`.repo`)들이 모여 있는 핵심 경로
- `yum clean all` : 저장소 설정이 바뀌었을 때, 기존에 내려받았던 찌꺼기 패키지 정보와 캐시를 싹 지우고 저장소 목록을 새로 고치는 명령어

# 10
[문제]
> 다음은 다운로드 받은 소스 파일의 내용만을 확인하는 과정이다. (괄호) 안에 들어갈 내용으로 알맞은 것은?
```shell
# tar ( 괄호 ) php-8.2.7.tar.bz2
```

[보기]
- jxvf
- Jxvf
- jtvf
- Jtvf

[정답]
- jtvf

[해설]
> bzip2 로 압축된 파일은 j 옵션을 사용하고, 압축을 풀지 않고 내용 목록만 확인할 때는 t(list) 옵션을 사용한다. 파일을 지정하므로 f 옵션이 함께 필요해 'jtvf' 가 옳다.
> jxvf 의 x 는 압축을 실제로 푸는(extract) 옵션이므로 '내용만 확인'에 맞지 않다.
> Jxvf 의 대문자 J 는 xz 압축용이고 x 도 추출이라 모두 맞지 않다.
> j(bzip2)+t(목록 확인)+v(상세)+f(파일 지정) 조합으로 옳다.
> Jtvf 의 대문자 J 는 xz 압축용 옵션이라 bzip2 파일에 맞지 않다.
> tar 압축 옵션: z=gzip(.gz), j=bzip2(.bz2), J=xz(.xz). 동작 옵션: c=생성, x=추출, t=목록 확인. f 는 항상 대상 파일명을 지정한다

[정리]
- `tar` : 여러 개의 파일이나 디렉터리를 하나의 파일로 묶거나(아카이브), 묶인 파일을 다시 풀어주는 리눅스 표준 유틸리티 명령
- `bzip2` : 높은 압축률을 자랑하는 압축 도구로, tar에서 소문자 `j` 옵션을 매칭하여 사용함 (확장자: .bz2)
- `gzip` : 리눅스에서 가장 널리 쓰이는 표준 압축 도구로, tar에서 소문자 `z` 옵션을 매칭하여 사용함 (확장자: .gz)
- `xz` : 최신 기술로 압축률이 가장 우수하지만 시간이 오래 걸리는 도구로, tar에서 대문자 `J` 옵션을 매칭하여 사용함 (확장자: .xz)
- `c (Create)` : 새로운 tar 묶음 파일(아카이브)을 생성할 때 사용하는 행동 옵션
- `x (eXtract)` : 묶여 있는 tar 파일의 압축을 실제로 풀어내고 추출할 때 사용하는 행동 옵션
- `t (lisT)` : 압축을 풀지 않고, 묶음 파일 안에 어떤 파일들이 들어있는지 목록(내용)만 확인할 때 사용하는 행동 옵션
- `f (File)` : 작업할 대상 tar 파일의 이름을 직접 지정해 주는 필수 옵션 (항상 명령어 맨 뒤에 붙임)
- `v (Verbose)` : 파일이 묶이거나 풀리는 과정을 화면에 상세하게(실시간으로) 보여주는 옵션
